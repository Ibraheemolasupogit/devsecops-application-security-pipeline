Secrets/ingress precede first QA deployment because the current image lacks a production key source and explicit GRAA_ configuration. Durable persistence and trusted production authentication precede production rather than being deferred behind observability. OIDC role scaffolding belongs in foundation, operational proof in M5. Telemetry needed for safe rollout begins before the full M11 stack. Each milestone should be split further if a change cannot be reviewed/tested independently.

## Milestone 2 boundaries

Recommend focused rationalisation, not a runtime rewrite: classify tracked duplicate coverage/portfolio/Gitleaks files; distinguish fixtures from run artifacts; prevent test/generator mutations leaking into documentation changes; preserve checked-in historical bundles; plan workflow DAG and required checks. Update ignore rules only for proven generated artifacts. Establish current dependency-audit failures and Docker prerequisite diagnostics with no policy weakening. Define ECS archival path and verifier compatibility before moving files. Do not combine cleanup, EKS Terraform and production pipeline implementation in one milestone.

## Open decisions and stop conditions

Confirm budget/uptime, region/accounts, domain/certificate ownership, GitHub protection availability/reviewers, runner network, IdP role mapping, DynamoDB access patterns/consistency, evidence retention, RTO/RPO and signing trust. Validate supported SDK/controller/cluster versions at implementation time. Stop promotion on failed/missing scanner evidence, unsafe test target, unapproved digest, expired exceptions, non-durable production state or unresolved required approvals. Local final-validation success alone cannot satisfy those conditions.
